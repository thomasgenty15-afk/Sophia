- Owner runtime: `track_progress_plan_item/intake` (détection d'assertion vs question de vérification) + gate d'effet sous owner de statut.
- Meilleure correction: l'intake track doit distinguer **assertion de complétion** (« j'ai fait X ») d'une **question de vérification** (« j'ai bien coché X ? ») et ne pas émettre d'effet durable sur la seconde ; ne pas s'appuyer sur `already_tracked_today` comme seule barrière. Test d'invariant : « mon suivi c'est bien X coché ? » → 0 requête de track (pas seulement blocked), owner status/verify.
- Pourquoi ce n'est pas un patch local: c'est la frontière assertion/interrogation de l'intake track + priorisation du chemin verify, pas une regex.

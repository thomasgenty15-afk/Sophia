## R1-B01 — Co-demande track 2 items: 1 seul émis + claim sur l'item manquant

- **Bug id**: R1-B01
- **Tours**: T2 (contre-preuve honnête T3)
- **Famille**: BF-AGENDA-01 (volet rendu: BF-LEDGER-01)
- **Domaine owner**: dispatcher global (émission direct_effects) + garde de rendu `stripTrackClaimWithoutCommit` (run.ts)
- **Source amont**: le frame ne porte qu'UN direct_effect track quand le user co-liste 2 items du plan (« j'ai activé le temps d'écran limité, et j'ai déjà choisi mon activité de ce soir »). La doctrine P10-C (alex-hard24 R1-B04, N entrées) n'est pas tenue à l'émission en réel. La garde P10-C de rendu est inopérante par construction: condition `anyCommitted ⇒ no strip` (vraie ici, commit du 1er item) + motif lexical « les deux sont pris » non matché par « j'ai aussi noté ton activité : aquarelle ✅ ».
- **Symptome visible**: « C'est fait pour le temps d'écran limité, et j'ai aussi noté ton activité de ce soir : aquarelle. ✅ » — l'aquarelle n'est nulle part.
- **Preuve systeme**: turn `ed5741fc` — direct_effects: 1 seul (`e31276ed`); ledger requested 1/committed 1; DB `user_plan_item_entries` = 1 ligne (`2bd43d40`), zéro ligne pour `f539e68c` (Choisir une activité de soirée); `system_error_logs` guards: 0 ligne.
- **Correction attendue**: (1) parité de cardinalité track portée au frame — N items du plan nommés dans un report ⇒ N requested (symétrie exacte de P8-A côté rappels), avec clarify nominative par item si un item est irrésoluble; (2) garde de rendu par-item: un claim d'enregistrement nommant un item SANS commit de cet item est retiré même quand un autre commit coexiste (le repli nomme ce qui a réellement été noté).
- **Statut**: fix_applied
- **Fix reference**: P12-B (doctrine 2e INVALIDE eva T2 + test mécanique count-items) + P12-C (parité PAR ITEM : claim additif sur item non commis strippé même avec commit coexistant)
- **Tests requis**: triplet émission (2 items nommés ⇒ 2 requested; paraphrase; anti-FP: 1 item + détail non-plan ⇒ 1 requested); test garde: claim nommant item non-commis avec commit coexistant ⇒ strip + ligne guards; run réel de revalidation.
